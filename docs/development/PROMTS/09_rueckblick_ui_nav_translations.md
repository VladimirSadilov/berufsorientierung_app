# Промпт 09: публичный UI Rückblick, навигация и переводы

Ты работаешь в проекте `berufsorientierung_app`. Реализуй клиентскую часть публичной страницы `/rueckblick` и пункт меню.

Промпт должен быть исполним после серверного этапа в отдельной сессии: если `+page.svelte` уже существует как временная заглушка из промпта 08, замени ее полноценным UI; если полноценный UI уже частично реализован, исправь только несоответствия.

## Сбор контекста

1. Перейди в корень проекта `berufsorientierung_app`.
2. Прочитай разделы ТЗ: 12, 12.4, 15 и критерии "Rückblick" из 16.
3. Осмотри файлы:
   - `src/routes/rueckblick/+page.server.ts`;
   - `src/routes/events/+page.svelte`;
   - `src/routes/reviews/+page.svelte`;
   - `src/lib/components/layout/Header.svelte`;
   - `src/lib/stores/language.ts`;
   - `static/translations/de.json`;
   - `static/translations/en.json`;
   - `static/translations/ru.json`;
   - `static/translations/uk.json`.
4. Изучи текущий способ построения навигации и перевода публичных страниц.

## Задача

Создай `src/routes/rueckblick/+page.svelte`.

Страница должна:

- показывать заголовок и описание через переводы;
- типизировать `data` через экспортированный тип из `./+page.server`, если он есть;
- показывать форму фильтров с `method="GET"`;
- поддерживать фильтры:
  - мероприятие;
  - дата от;
  - дата до;
  - сортировка;
- сохранять текущие выбранные значения из `data.filters`;
- показывать сетку медиа;
- показывать пустое состояние, если media нет;
- показывать пагинацию;
- pagination-ссылки должны сохранять текущие фильтры `eventId`, `dateFrom`, `dateTo`, `sort` и менять только `page`;
- отправка формы фильтров должна сбрасывать страницу на первую: не отправляй старый `page`, либо явно ставь `page=1`;
- не монтировать и не загружать видео до клика пользователя;
- использовать thumbnail или fallback-плитку для видео;
- корректно обрабатывать ошибку загрузки конкретного media-URL, не ломая всю страницу.
- для видео до клика показывай thumbnail/fallback без `<video src=...>`; после клика монтируй `<video preload="none" controls>` с `src` и запускай воспроизведение только по пользовательскому действию.
- если media URL изображения ломается, скрывай/заменяй только эту плитку, не очищая всю сетку.

Обнови `Header.svelte`:

- добавь пункт `Rückblick` с URL `/rueckblick`;
- ключ перевода `nav.rueckblick`;
- расположение строго сразу после `Bewertungen` / `/reviews`.

Добавь переводы в `de.json`, `en.json`, `ru.json`, `uk.json`:

- `nav.rueckblick`;
- заголовок/описание страницы;
- labels фильтров;
- значения сортировки `newest` и `oldest`;
- пустое состояние;
- pagination labels;
- aria-label для play-кнопки, если проект переводит такие строки.

В немецком переводе `nav.rueckblick` должен быть ровно `Rückblick`.

## Ограничения

- Не реализуй админку медиа.
- Не меняй DB-запросы, кроме минимальной правки типа данных, если UI не компилируется.
- Не используй autoplay.
- Не ставь `src` видео до пользовательского клика.
- Не показывай скрытые, просто загруженные или не подтвержденные для публикации media; это должно быть гарантировано server route/DB-функцией через `status = 'uploaded'`, `show_on_rueckblick = 1`, `publication_approved_at IS NOT NULL`.

## Проверка

1. Запусти `npm run check`.
2. Проверь валидность всех четырех JSON-файлов.
3. Проверь кодом, что пункт меню расположен после `/reviews`.
4. Проверь кодом, что `<video>` не получает `src` до клика.

## Критерии приемки

- URL `/rueckblick` имеет публичный UI.
- Вкладка `Rückblick` добавлена правее `Bewertungen`.
- Немецкий label равен `Rückblick`.
- Форма фильтров отправляет GET-параметры.
- Сетка показывает только данные, пришедшие из server route.
- Пустое состояние отображается без ошибки.
- Пагинация работает через query-параметр `page`.
- Ошибка загрузки одного media-URL не ломает страницу.
- Видео не загружается и не проигрывается до клика.
- Проект проходит `npm run check` или причина невозможности проверки описана в отчете.
