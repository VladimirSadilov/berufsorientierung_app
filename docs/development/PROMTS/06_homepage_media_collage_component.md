# Промпт 06: компонент HomepageMediaCollage

Ты работаешь в проекте `berufsorientierung_app`. Создай только переиспользуемый компонент медиа-коллажа для главной страницы.

Промпт должен быть исполним в отдельной последовательной сессии: если компонент уже существует, сначала проверь его против требований и правь только несоответствия.

## Сбор контекста

1. Перейди в корень проекта `berufsorientierung_app`.
2. Прочитай разделы ТЗ: 9, 11, 15 и критерии "Главная страница" из 16.
3. Осмотри текущие компоненты и стиль:
   - `src/lib/components/events/EventCard.svelte`;
   - `src/lib/components/ui/Button.svelte`;
   - `src/lib/components/layout/Header.svelte`;
   - `tailwind.config.js`;
   - `src/lib/types/eventMedia.ts`.
4. Проверь, есть ли папка `src/lib/components/media`; если нет, создай ее.

## Задача

Создай компонент `src/lib/components/media/HomepageMediaCollage.svelte`.

Пропсы:

```ts
import type { PublicEventMedia } from '$lib/types/eventMedia';

let { media } = $props<{ media: PublicEventMedia[] }>();
```

Требования к layout из раздела 11:

- mobile-first;
- 1 элемент на mobile;
- 2 элемента на tablet;
- 3 элемента на desktop;
- все видимые элементы находятся в общем контейнере;
- контейнер имеет тонкую синюю рамку, скругленные углы и легкую тень;
- используй цвета проекта, прежде всего `primary`/blue;
- стрелки слева и справа внутри контейнера;
- стрелки белые внутри синего круга;
- нажатие на стрелку сдвигает коллаж на 1 медиа-элемент;
- если media меньше видимого количества, показываются доступные элементы без поломки layout;
- если переключать нечего, стрелки скрыты или disabled.
- вычисляй `visibleCount` в компоненте по breakpoints проекта: SSR/default = 1, tablet = 2, desktop = 3; обновляй его на resize через `onMount`, не обращаясь к `window` во время SSR.
- рендерь только текущий slice длиной `visibleCount` (или меньше, если media меньше). Не рендерь desktop-элементы и не скрывай их только CSS-ом на mobile, потому что это смонтирует лишние видео.

Требования к производительности:

- не рендерить все 330 потенциальных элементов;
- рендерить только текущий видимый window; соседний элемент допустим только если он не является смонтированным `<video>`;
- изображения используют `loading="lazy"` и `decoding="async"`;
- видео не получает `src` до клика пользователя.

Требования к видео:

- autoplay запрещен;
- `<video preload="none">`;
- поверх preview кастомная play-кнопка;
- видео начинает играть только после клика;
- при отсутствии thumbnail показывается fallback-плитка с play-кнопкой;
- отсутствие thumbnail не блокирует запуск видео;
- при переключении стрелками активное видео останавливается;
- при unmount компонента активное видео останавливается.

Доступность:

- кнопки стрелок имеют `aria-label`;
- play-кнопка является настоящей `<button>`;
- для изображений используй `alt_text`; если его нет, `alt=""`.

## Ограничения

- Не подключай компонент в `+page.svelte` в этом промпте.
- Не создавай публичную страницу `/rueckblick`.
- Не добавляй сторонние библиотеки.
- Не монтируй скрытые видео заранее.

## Проверка

1. Запусти `npm run check`.
2. Проверь кодом, что `<video>` не имеет `src`, пока пользователь не нажал play.
3. Проверь кодом, что компонент рендерит window, а не весь массив `media`.

## Критерии приемки

- `HomepageMediaCollage.svelte` создан и использует Svelte 5-стиль.
- На desktop видно до 3 элементов, на tablet до 2, на mobile 1.
- Стрелки сдвигают window на 1 элемент.
- Активное видео останавливается при переключении и unmount.
- Видео не загружается и не проигрывается до клика.
- Изображения lazy/async.
- Компонент корректно работает с 0, 1, 2 и большим числом media.
- Проект проходит `npm run check` или причина невозможности проверки описана в отчете.
