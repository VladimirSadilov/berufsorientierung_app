# Промпт 03: корректное определение активных и прошедших мероприятий

Ты работаешь в проекте `berufsorientierung_app`. Исправь только логику активных и прошедших мероприятий через `end_date`.

## Сбор контекста

1. Перейди в корень проекта `berufsorientierung_app`.
2. Прочитай разделы ТЗ: 4, 10, 15 и критерии "Главная страница" из 16.
3. Осмотри файлы:
   - `src/lib/server/db/events.ts`;
   - `src/routes/+page.server.ts`;
   - `src/routes/events/+page.server.ts`;
   - `src/lib/types/event.ts`.
4. Найди все вызовы `getActiveEvents` и `getPastEvents` через `rg "getActiveEvents|getPastEvents" src`.

## Задача

В `src/lib/server/db/events.ts` измени определение активных и прошедших мероприятий:

- активное мероприятие:
  - `e.status = 'active'`;
  - `COALESCE(e.end_date, e.date) >= ?`;
  - сортировка остается `e.date ASC`;
- прошедшее мероприятие:
  - `COALESCE(e.end_date, e.date) < ?`.

Сохрани текущее поведение `is_listed`:

- по умолчанию из ТЗ `is_listed` остается фильтром только для публичной страницы `/events`, если текущий код уже делает это после вызовов DB-функций;
- не добавляй `e.is_listed != 0` в `getActiveEvents` и `getPastEvents`, если в коде нет явного такого правила.

## Ограничения

- Не подключай коллаж в этом промпте.
- Не меняй UI.
- Не меняй маршруты, кроме минимальной адаптации, если сигнатура функций уже требует этого.
- Не меняй смысл статусов мероприятий.

## Проверка

1. Запусти `npm run check`.
2. Если есть тесты для `events.ts`, добавь кейс: мероприятие с `date` в прошлом и `end_date` в будущем остается активным.
3. Если тестов нет, в итоговом отчете явно опиши ручную проверку SQL-условий.

## Критерии приемки

- `getActiveEvents(db)` использует `COALESCE(e.end_date, e.date) >= ?`.
- `getPastEvents(db)` использует `COALESCE(e.end_date, e.date) < ?`.
- Активные мероприятия сортируются по `e.date ASC`.
- Мероприятие, которое началось, но еще не закончилось, не попадает в прошедшие.
- Поведение `is_listed` соответствует разделу 4.3 ТЗ.
- Проект проходит `npm run check` или причина невозможности проверки описана в отчете.
